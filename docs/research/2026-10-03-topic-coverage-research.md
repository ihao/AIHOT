# 9BTC 主题覆盖评估与预测市场方向

评估日期：2026-10-03（北京时间）。本文件记录研究结论和配置快照，不代表生产变更已经执行。公开主题和生产验收由本次主任务另行记录。

## 判断

现有 8 个主题适合覆盖核心公链、链上金融、风险与研究，但还不能代表完整的 Web3 行业方向。最明显的问题是：8 项中只有 DeFi、稳定币与 RWA 属于横向领域；Bitcoin、Ethereum、Solana 是项目/网络主体，安全、监管和研究是内容类型。不能用 8 这个数字判断行业覆盖率。

本次优先增加用户明确希望追踪的“预测市场”。下一轮最值得补充的是“公链与扩容/跨链”“钱包、托管与支付”“交易所、衍生品与机构资本”。隐私与 ZK、Web3 AI、DePIN、消费应用也有价值，但建议先通过标签观察有效内容密度，再决定是否开放独立入口。该优先顺序是编辑判断，不是基于市场规模排名或投资建议。

## 当前配置和实际缺口

以下依据本次读到的 `industry/topics.json` 和 `industry/taxonomy.ts`，不根据记忆推断。

| 当前主题 | 配置组别 | 已覆盖 | 主要边界或缺口 |
|---|---|---|---|
| Bitcoin | 项目与机构 | 网络、协议、生态 | 仅 BTC 涨跌不能证明主体；矿业/算力/托管等需要明确证据与标签 |
| Ethereum | 项目与机构 | 升级、扩容、生态 | 无法代替整个多链基础设施、L2、跨链领域入口 |
| Solana | 项目与机构 | 网络、客户端、性能、生态 | 无法代替其他公链和跨网络基础设施 |
| DeFi | 方向 | 去中心化交易、借贷等链上金融机制 | 预测市场可与 DeFi 关联，但有独立的事件合约、结算和争议语义 |
| 稳定币与 RWA | 方向 | 发行、储备、赎回、资产代币化 | 当前定义没有完整涵盖支付、钱包、托管、法币出入金 |
| 安全事件 | 内容形式 | 漏洞、攻击、损失、处置 | 属于跨方向的事件过滤器 |
| 政策与监管 | 内容形式 | 政策、立法、执法、声明 | 属于跨方向的事件过滤器 |
| 研究与数据 | 内容形式 | 链上、技术、市场研究 | 属于跨方向的内容过滤器，不能承接所有遗漏赛道 |

底层 7 类已经包含“公链与基础设施”和“项目与商业”。因此部分消息可以进入公开池，只是主题页缺少聚合入口；这属于浏览覆盖不足。预测市场还缺少正式主题标签和清晰边界，属于语义覆盖不足。修复入口与修复采集信源是两个独立步骤：主题存在不意味着持续有稿，来源 HTTP 可用也不意味着有有效产出。

## 预测市场为什么应独立成方向

预测市场围绕一个可结算的事件结果买卖合约或结果份额，价格表达参与者的市场判断。Ethereum 官方将其单列为应用方向；Polymarket 的价格/订单簿说明也明确区分价格形成与结果结算。[Ethereum：预测市场](https://ethereum.org/prediction-markets/)、[Polymarket：价格与订单簿](https://docs.polymarket.com/concepts/prices-orderbook)。

建议名称“预测市场”，slug `prediction-markets`，放在 `field` 方向组；关联 DeFi、政策与监管、安全、研究与数据。主题核心应是平台和市场机制的实质变化：交易机制、费用和流动性安排、市场创建与规则、预言机、结算、争议处理、治理、融资合作，以及可复核的方法和数据。这个范围不需要为 Polymarket、Kalshi、UMA 各开一个主方向。

需要纳入的主要观察对象：

| 对象 | 一手资料所支持的范围 | 9BTC 可追踪的信息 |
|---|---|---|
| Polymarket 国际平台 | CLOB 价格由供求形成，链下撮合、链上结算；每个市场有明确结果来源、时间和边界条件，使用 UMA 处理结算提案及争议 | 协议/接口变更，市场规则与争议进展，费用/流动性机制，经过核实的运营变化 |
| UMA | 乐观预言机与争议仲裁系统；官方将 OOv2 预测市场与 OOv3 数据断言用例区分 | 预言机升级，提案与挑战规则，DVM 投票、治理和争议流程 |
| Kalshi | 每个市场有自身规则、核验来源和结果条件；CFTC 当前登记列为 DCM | 新产品与结算规则，监管文件、市场结构和经过核实的公司进展 |

依据：[Polymarket：价格与订单簿](https://docs.polymarket.com/concepts/prices-orderbook)、[Polymarket：结算](https://docs.polymarket.com/concepts/resolution)、[UMA 官方文档](https://docs.uma.xyz/)、[Kalshi：市场规则](https://help.kalshi.com/en/articles/13823822-market-rules)、[CFTC：Kalshi 当前登记](https://www.cftc.gov/IndustryOversight/IndustryFilings/TradingOrganizations/42993)。

Polymarket 文档列出的结算状态包括提案、挑战、第二轮提案和可能升级的 DVM 投票；未争议提案与已完成结算必须分别表述。该文档与帮助中心的旧说明在流程细节上存在版本差异，新闻应以目标市场的当前规则和链上状态为准，专题定义不写死押金或争议时长。[Polymarket：结算](https://docs.polymarket.com/concepts/resolution)、[Polymarket：争议帮助页](https://help.polymarket.com/en/articles/13364551-how-are-markets-disputed)。

监管归属也必须注明平台实体与地区。CFTC 当前 DCM 名录分别列出 Kalshi 和 `QCX LLC d/b/a Polymarket US`；国际 Polymarket 文档另有 US 文档入口。不能把某一实体的监管状态推广为所有同名平台、市场或地区的状态。[CFTC：DCM 名录](https://www.cftc.gov/IndustryOversight/IndustryFilings/TradingOrganizations?Status=Designated&col=Status&dir=ASC)、[Polymarket 文档入口](https://docs.polymarket.com/)。本评估仅判断资料和主题边界，不对交易资格或具体合约合法性作结论。

## 预测市场内容边界

建议收录：

- 平台产品、交易规则、结算机制或预言机的可核实变化。
- 已发生的重大争议、暂停、漏洞或资产损失，以及后续处理。
- 有原始文件的监管、立法、执法和司法进展，明确当前阶段。
- 带时间、平台、样本范围、方法和来源的数据研究。
- 与行业产生实质关系的市场信号；报道中明确其只是某平台某时点的隐含概率。

需要避免自动归入该方向的情况：

- 普通分析师的 BTC/ETH 目标价、技术分析、涨跌预测，没有事件合约或预测市场关系。
- 仅出现“预测”“市场”“概率”字样的新闻。
- 只把 UMA 代币价格当作预言机项目进展。
- 单纯重复体育比分、选举口号或娱乐竞猜，没有平台、机制、监管或可靠研究价值。
- 把“市场显示 70%”改写成“事件已证实”“真实概率就是 70%”或确定性结论。

以上是建议的编辑规则。Polymarket 官方解释，页面报价可能是买卖价中点，较宽价差时可能显示最后成交价；其价格表达市场参与者判断。Kalshi 也把价格说明为市场赋予的概率。因此引用概率需要保留时间、平台、报价性质和相关市场规则，不能用报价替代事件证据。[Polymarket：价格与订单簿](https://docs.polymarket.com/concepts/prices-orderbook)、[Kalshi：价格如何确定](https://help.kalshi.com/en/articles/13823836-how-are-prices-determined)。

建议的正反样本：

| 样本 | 是否进入预测市场 | 原因 |
|---|---|---|
| Polymarket 调整结算或费用规则 | 是 | 可核实的平台机制变化 |
| UMA 公布某市场的争议投票状态 | 是 | 预测市场基础设施与结算争议 |
| CFTC 发布某事件合约相关文件 | 是，兼政策与监管 | 明确关联的监管进展 |
| 某平台“降息概率升至 70%”，有时点和市场链接 | 可进入研究；是否精选另行判断 | 是市场信号，不是降息已发生 |
| 分析师预测 BTC 年底涨至某价格 | 否 | 普通资产价格预测 |
| UMA 代币单日上涨，没有协议事件 | 否 | 代币行情没有证明平台或预言机变化 |
| 某球队赢球，正文未讨论预测市场 | 否 | 普通体育结果 |

## 其余遗漏方向的优先级

| 优先级 | 建议方向 | 当前承接方式和增量价值 | 建议处理 |
|---|---|---|---|
| 本次 | 预测市场 | 目前没有独立标签/专题，事件结果合约与结算争议应有明确边界 | 新增方向 |
| 下一轮优先 | 公链与基础设施 | 底层已分类，但 Bitcoin/Ethereum/Solana 三主体无法代表其他公链、L2、数据可用性、跨链、开发工具 | 开横向入口，可先用现有 `公链/基础设施` 标签，不必再复制底层分类 |
| 下一轮优先 | 钱包、托管与支付 | 稳定币/RWA 当前主要讲资产发行与储备；用户入口、账户、密钥、托管、支付和出入金分散在项目商业/基础设施中 | 建议独立方向，保留与稳定币/RWA 交叉 |
| 下一轮优先 | 交易所、衍生品与机构资本 | 中心化交易/清算/托管、衍生品机制、ETF和机构资金变化不能全部由 DeFi 覆盖 | 建议独立方向；按机制/正式文件/有方法数据收录，压制上币促销和涨跌噪声 |
| 观察 | 隐私与 ZK | 既可能涉及扩容，也可能涉及身份、支付和数据保护 | 先加标签或基础设施子专题；ZK validity proof 不自动等于隐私交易 |
| 观察 | Web3 AI、DePIN | AI 钱包/链上动作与分布式无线或算力网络是不同用例 | 分别观察，不强行合并成一个赛道；核验真实产品/使用量再决定入口 |
| 观察 | NFT、游戏、社交与数字身份 | 现有两个金融方向承接不了全部消费应用 | 先以“消费应用”标签观察，再按有效供稿量决定是否独立；身份基础设施可与钱包交叉 |

支撑以上缺口判断的第一方用例：

- Ethereum 官方扩容和桥文档分别描述链外执行方案和跨网络资产/消息传输，这些范围超出某一个公链项目的进展。[扩容](https://ethereum.org/developers/docs/scaling/)、[跨链桥](https://ethereum.org/developers/docs/bridges/)。
- Circle 官方提供钱包及支付基础设施，涵盖支付与应用内资产存取；Coinbase Prime 官方说明则同时涉及机构交易、融资、托管和风险工作流。这证明钱包/支付和机构市场具备不同于稳定币储备、DeFi 的产品机制，但不证明这些入口的实时可采集性。[Circle 支付](https://www.circle.com/use-case/payments)、[Circle 钱包](https://www.circle.com/blog/getting-started-with-programmable-wallets-circles-wallet-as-a-service-product)、[Coinbase Prime](https://www.coinbase.com/prime)。
- Ethereum 官方明确有效性证明与零知识隐私是不同属性，ZK rollup 不自动使交易保密；应避免将两者混作同一分类事实。[ZK rollup](https://ethereum.org/developers/docs/scaling/zk-rollups/)。
- Coinbase 的 AgentKit 官方仓库提供 AI agent 钱包与链上交互；Helium 官方文档描述由社区 Hotspot 参与的 IoT 和移动网络。前者可以追踪钱包权限/支付/可验证交互，后者可以追踪实际覆盖和业务流量，代币价格或“AI”营销文字不足以证明相关产品变化。[Coinbase AgentKit](https://github.com/coinbase/agentkit)、[Helium 文档](https://docs.helium.com/)。
- Ethereum 官方分别介绍链上游戏和去中心化社交；NFT 既可表示游戏资产，也可用于内容和身份相关应用。建议关注产品、真实用户与权利机制，先避免拆成大量空专题。[游戏](https://ethereum.org/gaming/)、[社交](https://ethereum.org/social-networks/)。

## 实施和验收建议

三组继续保留：项目/网络主体、行业方向、跨方向的内容类型。用户可以按主体找 Ethereum，也可以按方向找预测市场，还可以按内容类型找监管，两种关系可以交叉，无需把一个稿件强行归到唯一主题。

只新增一个专题配置仍可能出现空页面，应同时覆盖：规范标签与同义词、理解/核验提示词、主题聚合、现有公开稿的确定性标签修正、主题 API/页面验收。不要用平台信源标签强制给每篇稿件加专题；不要给未核验稿补公开资格。既有稿修正可以依据明确名称与上下文进行，不应重新触发模型请求或回补过期历史。

未来增加其他方向前，核对最近一段有效公开内容中该方向的数量、来源独立性和读者需求。当前一次生产快照不能证明长期内容密度，建议避免因新增导航而宣称已经全面覆盖。

## 研究方式与限制

按 `research` 技能以官方文档、代码仓库、监管登记为依据；按 `agent-reach` 的搜索路由尝试 Exa，连接协商失败后使用官方网页读取。仅研究主题边界，没有修改配置、启停信源、生产数据库、公开资格或评分门槛，没有调用付费模型。`agent-reach check-update` 已执行，3 次重试后仍因网络连接失败，无法确认可用新版本。
