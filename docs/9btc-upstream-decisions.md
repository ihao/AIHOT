# 9BTC 与上游持续整合的差异化决策

本文件是后续合并上游时的长期决策依据，不是一次性差异清单。首次建立：2026-10-15；已吸收上游基线：`e57da5a4f151892a217529744cd68803aec580df`；业务分支：`feat/9btc-web3`。每次同步先阅读本文件，再核实当时生产实际版本、设置和回执，不能用历史快照代替现状。

## 决策优先级

1. 使用者最新明确决定优先；先判断该决定是否已实施，不能把文字约定当成上线证据。
2. 架构、通用修复、数据库迁移、日报生成器及任务基础设施采用上游标准实现。
3. 9BTC 已确认的发布/精选标准、来源授权、品牌和行业设置保留，不因框架更新自动放宽。
4. 涉及新增付费调用、历史重跑、未知计费、金额或请求预算时，保留 9BTC 消耗保护后再适配上游。不得靠降低质量门槛节省费用，也不得未经决定开启限额或增加默认模型。
5. 原始材料、分析、核验归档、回执、费用账本、既有报告和不可变行情绑定保全；影响已有数据的上游迁移须有可恢复备份和升级演练。

## D01：框架架构跟随上游

前端只通过 HTTP 读取 API；后端持有数据库和模型凭据；worker 执行采集、模型及任务。所有公开出口共用 `publication/` 读取与发布规则，不新增绕过规则的站点出口。行业知识放 `industry/`，身份、模型选择和文案放 `site/`，独有能力优先用 `modules/`。

合并时吸收上游的采集解析、队列、回执、编辑、归组、读取层、安全和前端修复；不为保留旧目录结构复制第二套框架。必要的站点接点保持窄、可审计，并在本文件说明理由。

## D02：发布与精选保留 9BTC 的独立判断和质量门禁

长期原则：模型生成的标题、摘要或推荐理由本身不是事实核验，也不能作为自己的发布许可；发布与精选沿用已验收的生产判断、来源/事实依据和门禁，框架优化不自动取代这些决定。

**建立文件时的真实生产实现需要明确区分：**应用 `47994a7` 已采用上游 4.0 编辑链和 9BTC 质量修复；它并未运行旧版独立证据核验/自动改写任务。`automatic_verifications`、旧审核和报告版本表是只读历史归档，存在这些记录不能证明旧核验链正在生效。当前实际门禁是：

- 预筛只有 PASS 才继续评分及写作；UNKNOWN 等材料的新修订，不能因生成了摘要而自动公开。
- 全部动态必须有确认的相关性、有效评分及可展示内容；`SELECTION.publicFloor=10`，未评分和低分只内部留存，低分不购买公开用文案。
- 精选评分独立进行两次，分级门槛保持 T1=60、T1_5=65、T2=76，理解门槛为 50；够分只是候选，归组身份/新增价值判断完成后才准入。
- 统一发布层读取保存的原始预筛结果，旧 relevance=pass 不能覆盖原 UNKNOWN；人工 score=null/0 不回退旧高分；拒收内容的列表、详情、搜索、RSS、API、Agent/MCP 和事件引用保持同一门禁。

用户所指“独立核验”若是旧版对原稿进行独立一手证据核验的完整流水线，则这是**需另行实现及验收的能力**，不能用上述相关性/评分/归组判断替代或声称已经恢复。本次只新增决策文件并发布既有整合代码，不恢复旧任务、不重新核验历史文章。未来改变该机制必须明确证据输入、发布许可、稳定请求身份、计费边界和生产前后公开/精选集合，完成独立回归及上线验证。

## D03：迁移按上游执行，价格与预算独立适配

已发布 SQL 不改写、不删除或重新编号；按完整文件名记账，同号不同名分别执行。新的在线 DDL 沿用上游安全检查、锁等待/语句超时；索引用并发方式，不将大批文章回填混入发布迁移。

上游允许移除旧价格元数据，不能因此修改历史迁移或让金额预算失去依据。9BTC 已将 `per_request`、`verified_on`、`source_url`、`note` 保存在独立 `ninebtc_model_price_evidence`，基本模型与 token 单价仍读上游 `service_prices`；预算查询连接二者。

尚未执行历史 `0051` 的数据库由 `site/migrations.ts` 在该迁移同一事务内保全小量活动价格配置，失败时一起回滚；已执行的数据库不补造证据。价格更新须同时维护基本单价与证据，无核对依据时不宣称价格已验证。费用估算与真实供应商账单分开。

本次上游索引 `0085_grouping_decisions_fact_idx.sql` 和站点价格迁移 `0085_ninebtc_model_price_evidence.sql` 文件名不同，分别记账；现有生产 72 项升级到 73 项只新增一个索引，不重分析资料。下一次以实际新增文件为准，不硬套本次数量。

## D04：日报及任务采用上游机制，消耗例外明确保留

采用上游日报规则编排、周/月汇总、pg-boss 队列、定时注册、恢复及退役任务清理；北京时间日报 08:00、周一周报 10:00、每月 1 日月报 10:30，由统一站点配置驱动。排程每半小时检查；开始于首份日报之前的周/月不尝试成刊；没有材料不能伪造成有内容的报告。

9BTC 已确认的消耗例外是：三类报告自动启用，`catchUpHistory=false` 只生成最新到期一期；已有报告不改写，文章不因提示词或模型变化重跑。上游标准会遍历旧缺期，而当前站点不批量补旧缺期；这项差异不能被“按上游默认”一句话悄悄覆盖。若未来决定恢复历史补期，先明确其模型费用、报告边界和数据保全，再单独验收。

不注册旧独立 verification、旧日报生成/补期和重评分/改写任务。实际运行哪些任务，以当时 worker 代码及数据库排程为证据，不以遗留环境变量或归档表推断。

## D05：站点功能保留行业身份，通用体验采用上游

保留 9BTC 品牌、Web3 文案、七个稳定分类 key、行业主题及来源授权。来源种子只插入缺少的来源，不覆盖生产的启停、配置、许可和预算；默认只展示摘要与原文链接，全文展示/再分发须有明确授权。

采用上游未读筛选、目录滚动、导航布局、公开分类、安全及 SelectBench 修复。`NAV.hidden=[]` 保持默认热点和主题入口；预测市场保留跨类别筛选及搜索/跳转参数连续性，已撤下的独立预测市场侧栏不自动恢复。变更导航必须检查默认/非默认电脑侧栏、手机底栏、“我的”、直达和返回。

Coinbase BTC/USD 是站点模块：后台 5 分钟采集、浏览器可见时 10 分钟刷新；新闻首次入库报价不可变，未绑定的历史值不补造。保留 EU 本机 3109 入口、web 无后台凭据/数据库卷、worker 正常收尾宽限。

## D06：模型消耗与未知计费不可绕过

自动处理默认只接收来源时间最近 48 小时的有效资料；无日期、异常未来时间、过期或暂停来源不进入自动付费处理。同版本保存的分析不因提示词变化再次购买；恢复发布/归组复用保存结果，手工重评使用稳定标识，晚到旧响应不能覆盖新判断。

所有模型请求继续经过共享回执、请求次数预算、CNY 预留与结算、缓存 token 计价和供应商暂停机制。模型 unknown 不自动释放或重发；核对未计费才释放金额，核对已计费则保留账本。不清空历史账本、不把“估算节省”说成供应商账单下降。

模型选择以环境/后台已确认配置为准，站点 `DEFAULTS={}` 不擅自增加默认模型。新增改用词能力的 `industry/wording.ts` 保持空词表，因此默认新增此类调用为 0；未来启用词表需确认额外请求和预算。建立文件时金额硬限额关闭、数据库保存日/滚动 9 元；这些是初始快照，后续合并不得覆盖运营实际设置。

## 每次同步的执行依据

1. 读取本文件及当次 `AGENTS.md`，核实本地/远程 main、feature、生产镜像与实际设置；保留未提交工作，禁止输出凭据。
2. 正常增量 merge，保留上游祖先和业务历史，不 squash、不强推、不整树重置。对每个冲突按 D01–D06 判断，注明采用上游还是保留站点及理由。
3. 原 SQL 与费用关键文件逐字核对；新安装、生产基线升级及第二次迁移为空操作均验证。
4. 模型/采集测试使用独立 `_test`/`_ci` 库、本机假服务和外网阻断；执行类型检查、后端/网页回归、构建、页面/API/RSS/MCP 检查及相关真实浏览器验收。
5. 固定提交后再发布：保存并实际恢复备份，正常停止旧 worker，完成迁移后启动新版；在恢复后台前核对原始/分析/回执/报告/来源/预算与公开/精选集合，再检查真实任务及公网。
6. 将当次执行证据作为验收记录保留；本文件只更新长期决策与实现状态，不能把一次通过的数量当成永久保证。只在决策真正变化时改规则，注明日期、依据、影响、实施及验收状态。
