# 预测市场第九主题设计

用户已于 2026-10-03 明确选择“按此方案上线第 9 个主题”，批准的评估方案在主工作区 `docs/research/2026-10-03-topic-coverage-assessment.md`。本设计将同一范围落实为实施约束；不扩展其他建议方向。

## 目标与边界

增加 `prediction-markets` / 预测市场 / `field`，标签 `预测市场`，关联 DeFi、政策与监管、安全事件、研究与数据。覆盖 Polymarket、Kalshi 及明确相关的预言机、结算争议、平台发展、监管和研究。普通资产目标价预测、娱乐体育结果、下注推广不能仅因预测字样进入。市场隐含概率保留平台、时点、报价与市场规则，不能当作已确认事实。中心化平台不能因该标签变成 DeFi；UMA 一般预言机或代币消息必须有明确预测市场关系。

保留现有 8 个专题 URL、7 个分类、内容类型、评分数值与精选门槛。专题继续只读精选公开内容。生产候选关键词检索为18篇公开、0篇精选，因此允许专题暂无稿件，不用强行精选填充。

## 架构与数据流

行业配置定义专题、规范标签与明确词汇同义词。预筛明确允许预测市场平台实质变化；理解与结构化提示词识别该标签，规则保留报价/事实/结算和实体辖区的区分。既有发布读取层与页面自然聚合该标签，不新增读者模型调用。

分类提示词变更会改变 `AUTOMATIC_RULE_VERSION`。此前生产版本已核对为 `automatic-publication-v1:5c0e3a85b0b01eeb31df0874`。本次未改变评分、事实核验、安全规则或证据要求，因此可显式登记“本次新版本 → 这个先前版本”的一次兼容关系。仅当当前版本完全匹配登记键时才接受旧版本，未来任何规则变更默认失效；旧版本记录必须仍满足全部原稿/分析/来源/证据/副本/审核指纹检查。已有当前新版本记录时不得回退使用旧版本接受结果。兼容的已接受历史稿不触发批量分析；原核验记录、回执和历史均保留。

近一个月的公开候选逐篇核对；只有语义确定的稿件才在发布投影添加标签，不改原始分析、核验副本/指纹、精选状态或资格。日期不明、更早以及未公开候选不在此次修正范围。此为可审计的一次标签修正；重新分析后的标签由新理解规则产生。当前没有预测市场精选，修正标签不承诺页面出现稿件。

## 上线和恢复

在独立 Git 工作区修改，保留主工作区既有信源调整。固定提交构建部署，只更新9BTC三个应用角色；生产信源配置和数据保留，不运行会覆盖设置的初始化。先备份当前镜像与主题/修正记录，再以事务写入新专题与发布投影标签、审计日志；失败回滚事务或恢复此前镜像。涉及的线上配置必须与已测试提交相同。

## 验收

- 标签归一保留预测市场及明确英文/繁体同义词；普通价格预测/单独预测词不映射。
- 主题聚合包含标签匹配的精选公开稿，排除未精选/未公开稿；旧8专题行为不变。
- 兼容旧已接受核验仍公开；任意其他版本、旧分析、暂停来源、变更副本仍不能公开；当前新版本拒绝或等待时不回退旧结果。
- 兼容历史接受结果不被恢复扫描排队重跑；规则再次变化默认关闭兼容。
- 类型检查、项目要求的完整后端/网页验证和构建，必要时公开烟测。已知既有手动事件日期测试失败需分开报告。
- 生产主题 API 含第9项，专题页面200，三个角色使用新配置，旧公开可见集未因兼容失效减少，修正精选状态未改变，预算/历史处理不被重置。

主题数不受100个激活信源上限约束。本次不新增信源；现有信源启停、历史上限和预算策略均保留。
