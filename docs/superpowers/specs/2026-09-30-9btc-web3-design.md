# 9BTC Web3 热点与研究站设计

日期：2026-09-30。状态：用户已确认产品方向，待审阅本文。目标源码：[ihao/AIHOT](https://github.com/ihao/AIHOT)；本地克隆时 `main` 为 `885b736`。目标域名：`https://9btc.com`，部署在 OPS 记录的 EU 服务器。旧服务器与旧站不变；用户在新站通过验收后自行切换域名 A 记录。

## 目标与边界

9BTC 是面向中文资讯与研究用户的 Web3 热点站。它帮助读者找到可核验的重要变化，理解事件进展，并回到原始来源。首版免费、无需登录；保留网站、RSS、公开 API 与 MCP 阅读入口。站名为“9BTC”，副标题为“Web3 热点与研究”。

内容口径为“事实与研究优先”：优先协议升级、治理结果、安全事件及修复、监管原文、稳定币和链上数据研究、重要机构动态。纯价格波动、无证据预测、交易喊单、返佣和空投营销不进入精选。涉及价格时写清时间、单位和来源，不把相关性写成因果，不把资料摘要写成投资建议。原文版权属于来源方；默认仅展示摘要和原文链接。

首版不做钱包登录、交易、持仓、实时行情终端、会员收费和个性化推荐。周报/月报可保留原框架能力，但首版主要验收首页、全部动态、事件、专题和日报。

## 页面与内容结构

首页展示已审核的精选和事件热点；“全部动态”包含已审核内容及允许白天自动公开的低风险一手公告。事件详情显示事实摘要、进展和各条原始证据。日报在晚间审核后发布。来源与方法页面解释收录、筛选、AI 辅助和更正路径。

首版分类固定为七类：公链与基础设施、DeFi、稳定币与 RWA、安全、政策与监管、项目与商业、研究与数据。Bitcoin、Ethereum、Solana 等作为实体、标签或专题，不作为互斥分类。分类 URL key 与专题 slug 在公开上线前稳定，后续改名不随意改 key。

行业规则集中在 `industry/`：站点文案、分类实体、主题、筛选与写作提示词、门槛、品牌素材、使用规则和隐私说明。关闭 AI 模型榜与 Codex 监控；删除公开页面的 AI 示例文案和素材。保留原项目 MIT 许可与 NOTICE。

## 信源研究与入库门槛

信源单独做专题摸底，不把现有候选清单直接导入生产。研究逐项记录：来源主体与官方域名、内容范围、抓取方法及稳定性、日期/正文质量、重复率、频率与成本、使用及转载边界、是否值得进入精选。可先用公开、稳定的 RSS 和官方公告做开发验证；生产第一次 `seed` 前必须移除 18 个 AI 示例源，只保留研究后批准的 Web3 来源。后续新增来源也先试抓、审阅样本，再入库。

官方一手与媒体分级；治理论坛帖须区分发帖人意见和协议正式决定。只在有明确许可时展示站内全文。采集失败保留错误与最近成功时间，不生成虚构或无来源的内容。信源研究成果是单独的证据表及首批入库建议，用户可据此复核范围。

## 发布流程

采集、去重、预筛、评分、中文摘要和事件归组复用 AIHOT 主链路，但使用 Web3 的分类、术语、风险和评分标准。门槛用人工标注的 Web3 样本校准，不沿用 AI 示例门槛作为已验证数值。

公开内容分两路：

1. **白天有限自动发布**：只有经身份与抓取验证、明确列入白名单的官方一手来源，其低风险发布说明、技术更新等内容，才可自动进入“全部动态”。作为已公开条目，它也可通过自身详情页、搜索、“全部动态”RSS、公开 API 的全部动态查询和 MCP 搜索被找到；各出口读取同一公开版本。它不会自动成为首页精选、精选 RSS、事件热点、日报或周报/月报条目；事件归组可在内部运行，但公开事件页只引用已审核条目。安全事故、监管、资金损失、收益承诺、未经证实的重大数据及模型低置信度内容，即使来自官方来源也不走自动通道。
2. **晚间人工审核**：其余候选内容进入待审队列。用户每晚约 30 分钟查看来源、关键事实、标题摘要和归组；通过后可进入精选及相应公开出口，驳回或修改要留痕。审核通过前，详情、搜索、事件、热点、RSS、公开 API、MCP 和站点地图都不能泄露待审内容。素材或模型结果在审核后发生实质变化时，相关批准失效并重新待审。

日报在晚间审核后由已批准内容生成草稿，用户确认后发布；缺席审核、模型失败或无足够可靠内容时，保留上一期，不自动发空刊。已公开条目的来源正文或模型结果发生实质变化时，不用新版本自动覆盖旧公开版本：该条目先从各公开出口暂时下架并进入待审，审核通过才重新公开；下架期间已有日报中的引用标记为暂不可用。更正和撤稿也传播到所有公开出口，并标记已发布日报中的失效来源。后台提供待审数量、来源、变更记录和异常原因，优先显示安全、监管、金额及已公开后变化的内容；积压项保持待审，不因等待时间而自动放行。审核状态与现有公开可见性分开存储，以免“待审”被误当作“撤稿”。

## 运行与成本

源码只在 `ihao/AIHOT` 中开发管理，以固定提交部署。类型检查、前后端测试、Web 构建、迁移和站点 smoke 是合入与部署门槛。开发和测试默认关闭抓取、模型、推送和索引提交；真实小样本测试明确启用并记录模型调用、token 与成本。模型供应商、密钥和每日预算在首次真实测试前确定；密钥只放后端环境，不入库。

EU 上使用独立的 Docker Compose 项目、网络、数据库和数据卷；Web 只绑定 `127.0.0.1:3109`，由服务器现有 Caddy 代理 `9btc.com` 和 `www.9btc.com`。不启动源码内置 Caddy profile，不占用其他业务的 3000/3001/5432 宿主端口。设置独立管理员密码、会话与图片签名密钥、强数据库密码，生产启用可信代理设置。数据库和上传数据备份到服务器外，并做一次恢复演练。

## 验收与公开切换

公开前应看到真实 Web3 资料完成采集、筛选、归组、审核和日报闭环；逐项验证白天自动通道不会放行高风险条目，待审条目在所有公开出口不可见，撤稿更正同步生效。抽查中文摘要的主体、金额、链、时间和阶段；核对模型限额、任务失败、后台登录、移动端和备份恢复。若关键链路失败，不切 DNS。

EU 私有访问验收后，用户将 `9btc.com` 根域 A 记录切到 EU。切换后检查根域与 `www` 的 HTTPS、首页、详情、日报、RSS、API/MCP 和后台。旧站不迁移、不停机、不修改；DNS 回退只需恢复旧 A 记录。
