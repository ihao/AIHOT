# 生产模型金额预算与核验分流设计

用户已批准 `2026-10-04-daily-model-budget-plan.md` 的完整优化与生产实施。金额目标覆盖本站全部聊天、改写、向量与评测请求；金额不足时延后，不放行未核验内容。测试不访问外网，生产评测是授权的独立有界操作。

## 约束

- 保留当前精选阈值、事实授权规则指纹、已公开内容、来源授权、请求数预算与账本历史。
- 新模型、执行材料与输出配置只作用于新核验轮次；旧成功回执精确复用。金额策略启用时，模型 pending/unknown 禁止自动释放重买；人工恢复若确认未计费才释放金额，若已计费或结果未知则保留原额度并对新尝试再次预占。
- 不修改现有主提示词的授权语义。新执行策略可追加简洁输出要求，但必须持久化策略及配置指纹。
- 生产普通模型切换之前完成约 100 个来自真实文章的证据主张样本核对，包含可验证支持与明确数字/阶段/主体反例；人工用户标注不可伪称已存在。代理逐条整理的证据标准须明确标签来源及局限，不能拿现有 Max 判定充当事实标准。

## 金额预算

新增可启停的数据库金额策略：北京时间自然日上限 9 CNY，同时滚动 24 小时上限 9 CNY；日常运营目标 8 CNY。迁移默认关闭，生产发布时显式启用并审计。若现有窗口已超额，等待费用退出窗口，不能重置历史以释放额度。

使用 `service_prices` 的 CNY 实时价与缓存价，DeepSeek 按忙时上界预留；当前实用型号至少覆盖 Qwen3.8 Flash/Max、百炼 DeepSeek-V4.1-Flash 与 text-embedding-v4。价格缺失、不可靠 token 界或启用思考而无法约束输出时停止新模型发送，成功回执仍可复用。

`paidRequest` 在全局金额锁下检查金额、服务请求数、逻辑回执，并原子写入 attempt 与预占；全局锁在服务锁前，所有供应商共享。文字输入按序列化消息 UTF-8 字节数加协议余量做保守 token 上界，输出按实际发送 max_tokens 预占；多模态未有可靠边界时金额策略拒绝发送。向量按实际批次文本预占。独立预占元数据不改变旧逻辑请求键。

响应后按可信 usage 计算目录费用估算，缓存仅按返回命中量结算；费用标为 estimated，不能假称实扣。usage 缺失、异常、超出预占或 unknown 保留保守额度并使超界可见，不能释放成零。明确未接受请求的 400/401/403/404/422/429 或连接建立失败可以释放；5xx、发送后超时不能视为确定免费。重试新增预占。释放与结算事务与全局锁一致，避免并发额度过冲。

旧窗口请求按既有 usage 和经过核对的价格计入，保留原始回执；无可信 usage 的旧未知结果使用保守上界或冻结新调用，不能排除。金额窗口不受原请求数 `usage_reset_at` 影响。

后台只读显示金额上限、北京时间当天/滚动使用与预占、估算口径、等待状态。已有预算等待与重试通道继续沿用，金额错误信息保持可识别且带中文标签。

## 核验分流与执行策略

新增明确的百炼 DeepSeek preset，服务仍是 dashscope，同一凭据，不使用未配置的官方 DeepSeek preset；关闭思考，启用结构化输出。

新轮次持久化执行策略。首轮分流范围固定为普通一手官方信息（first_party=true 且无风险信号）；全部二手媒体与复杂风险保留 Max。以原始标题/正文、中文文案、分类与 itemType 的确定性风险信号路由；监管、攻击/损失、治理实施、材料冲突与复杂状态仍使用 Max。只有已通过评测的该范围使用 DeepSeek；其余范围不因数量比例扩张。路由只选择核验模型，不能取消一手证据门禁或变化评分标准。分流关闭时仍为当前模型。

新轮次使用有界输出，建议 4096 token，同时保留旧轮次 16384 的准确配置与输入。原文材料完整存储。材料压缩仅保留原文连续段落与真实 quoteId，去除完全重复段落；相关证据段必须保留条件、否定与相邻上下文，无法证明足够覆盖或超过限制时停止本轮付费核验，不静默截断证据。不能用生成摘要代替原文。

## 评测与上线

先运行纯逻辑与本机替身测试、金额并发/重试/未知回执集成测试、公开集合兼容测试。生产模型评测经同一金额与请求数预算，按当前额度分批执行，任何额度不足都等待；不绕过 guard。输入正文不进入公开验收文档，记录来源标识/哈希、样本类型、判断差异、token、费用与摘要检查结果。

质量门槛冻结为至少 100 个证据主张案例，其中至少 40 个在首轮路由范围内的支持案例、40 个同范围明确数字/主体/阶段/否定反例、20 个风险/二手边界案例。样本来自不少于 40 篇不同真实文章，额外记录文章数，不冒称 100 篇不同文章。范围内错误放行必须为 0，支持案例完整发布判定通过率至少 95%，结构/引用有效率必须 100%；所有差异均有原文核对结果且无未解释差异。使用最终部署的证据包、4096 输出与完整发布判定。结果、范围与数据哈希写入分流启用审计。若不合格，保留 Max 并上线金额与止损保护，明确说明分流未达门槛。样本结果只是当前范围证据，不等同于全业务质量证明。

发布分两阶段。先停止付费 worker，迁移、核对价格与历史账本、启用金额策略，再恢复新镜像 worker；普通分流仍关闭。随后评测经已启用金额账本，合格才启用分流。首次生产付费评测也不在保护外运行。

发布采用已验证提交的新镜像、增量迁移、受限私有配置复用。安全回滚仅恢复旧 API/web 并关闭两者模型安全阀，付费 worker 保持停止，直到带金额保护的镜像恢复；不能回滚到无金额保护的旧 worker。切换前后比较公开/精选 ID 集合，验证 API/web/worker 镜像、费用策略、模型配置、规则/来源授权一致性、网站/API/RSS/MCP smoke。实际持续账单降幅至少需要完整自然日，不能用瞬时换价估算当验收结论。
